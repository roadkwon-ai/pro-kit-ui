# 처음 보는 용어

튜토리얼에 나오는 말을 쉬운 말로 풀었어요. 다 외울 필요는 없고, 막힐 때 찾아보면 돼요.

> [!TIP]
> 처음에는 도구 표의 터미널·에이전트·프롬프트, 만들기 표의 라운드, 계정과 비용 표의 비밀값만 알면 따라 할 수 있어요.

용어는 다섯 묶음으로 나뉘어 있어요. 도구, 만들기, 디자인, 올리기, 계정과 비용 순서로 찾아보세요.

## 도구

| 용어 | 뜻 |
|---|---|
| 터미널 | 글자로 컴퓨터에 명령하는 프로그램. macOS는 "터미널" 앱, Windows는 Ubuntu 창 |
| 에이전트 | 대화로 부탁하면 코드를 쓰고 명령을 실행해 주는 AI. pro-kit-ui는 Claude Code, Codex, Antigravity, Grok Build를 지원하고, 튜토리얼은 Claude Code와 Codex로 확인했어요([에이전트별 차이](claude-code-and-codex.md)) |
| 세션 | 에이전트를 한 번 열어 대화하는 단위. 닫았다가 다시 열면 새 세션이에요 |
| 묻지 않고 진행하는 옵션 | 에이전트가 명령마다 허락을 묻지 않게 여는 옵션. `claude --dangerously-skip-permissions`, `codex --yolo` 등. [주의할 점](claude-code-and-codex.md#묻지-않고-진행하게-열기) |
| Codex CLI | 터미널에서 쓰는 Codex. Claude Code를 쓸 때도 설치하고 ChatGPT로 로그인해 두면 이미지를 그릴 수 있어요 |
| 프롬프트 | 에이전트에게 보내는 부탁 글. 튜토리얼의 프롬프트 블록을 복사해 붙여 넣어요 |
| 대화창 | 터미널에서 에이전트를 연 뒤 프롬프트를 입력하는 곳 |
| 스킬 | 에이전트가 읽는 작업 설명서. 부탁하면 에이전트가 알아서 골라 써요 |
| 호출률 | 에이전트가 필요한 스킬을 실제로 불러 쓴 비율 |
| 두뇌 | 요구 정리, 계획, 구현 진행, 디버깅을 이끄는 스킬 묶음. 프로젝트마다 하나를 고르고 여럿도 고를 수 있어요(첫 번째가 주 두뇌). 고르지 않으면 지금 에이전트가 내장 절차로 진행해요. 나중에 "두뇌를 openspec으로 바꿔줘"처럼 말로 바꿔요 |
| 과설계 방지 스킬 | 에이전트가 필요 없는 코드와 기능을 덧붙이지 않게 막아 주는 스킬. 설치할 때 하나를 골라요(예: ponytail). 계획, 구현, 코드 리뷰에서 "더 적게 만들 수 없나"를 먼저 따져요 |
| 하네스 | 에이전트가 정해진 순서와 검사를 지키며 일하게 만드는 규칙, 스킬, 자동 검사의 묶음. pro-kit-ui가 새 프로젝트에 설치해요 |
| pro-kit-ui | 새 프로젝트를 만들고 에이전트가 일할 환경을 갖춰 주는 생성기. 이 튜토리얼의 출발점 |
| Node.js, pnpm | 웹 서비스를 만들고 실행하는 데 필요한 프로그램과 그 부품 관리 도구 |
| git, 커밋, push | git은 파일이 바뀐 기록을 저장하는 도구예요. 기록 한 번을 커밋, 그 기록을 GitHub에 올리는 일을 push라고 해요 |
| 브랜치, merge, PR | 브랜치는 git 기록의 갈래예요. 본줄기(보통 `main`)를 건드리지 않고 따로 작업할 때 만들어요. 작업을 본줄기에 합치는 일이 merge이고, 합치기 전에 사람이 보고 허락하도록 GitHub에 올리는 요청이 PR(Pull Request)이에요. 프로킷은 처음에는 기본 브랜치에서 일해요. |
| diff | 파일이 바뀐 곳을 줄 단위로 비교해 보여 주는 것. 지운 줄과 더한 줄이 나와요. 에이전트와 리뷰어가 "무엇이 바뀌었는지"를 확인하는 기본 도구예요 |
| CLI | 터미널에서 명령으로 쓰는 프로그램. `claude`, `codex`, `git`, `pnpm`, `vercel`이 모두 CLI예요. 화면에서 누르는 앱과 달리 글자로 입력해요 |
| 서브에이전트 | 메인 에이전트가 일부 일을 따로 맡기려고 띄우는 보조 에이전트. 자기만의 대화와 권한 범위를 가져요. pro-kit-ui는 구현 수행자, 리뷰어, 분석 에이전트 같은 전문 서브에이전트를 `.claude/agents` 폴더에 설치해요([위임 에이전트와 리뷰 에이전트](https://github.com/roadkwon-ai/pro-kit-ui/blob/main/handbook/concepts/agent-roles.md)) |
| 플러그인 | 에이전트에 스킬, 훅, 명령을 한꺼번에 더해 주는 묶음 설치 상품. 두뇌와 과설계 방지 스킬 중 일부가 플러그인으로 들어와요 |
| 훅 | 에이전트가 파일을 고치거나 세션을 열 때처럼 정해진 순간에 저절로 돌아가는 작은 프로그램. 프로킷에서는 화면 파일을 고칠 때 디자인 검사기가 도는 것이 대표예요 |

## 만들기

| 용어 | 뜻 |
|---|---|
| 프로젝트 | 서비스 하나를 이루는 파일이 모두 들어 있는 폴더 |
| 모노레포 | 웹 앱, API, DB 같은 여러 부분을 한 저장소(프로젝트 폴더)에 함께 담은 구조. pro-kit-ui로 만든 프로젝트가 이 모양이에요 |
| 화면과 서버 | 화면은 브라우저에 보이는 부분, 서버는 뒤에서 데이터를 저장하고 꺼내 주는 부분 |
| DB(데이터베이스) | 회원, 글, 주문처럼 서비스의 데이터를 저장하는 곳 |
| 로컬 | 내 컴퓨터. |
| `localhost:3001` | 내 컴퓨터에서 실행 중인 서비스를 브라우저로 여는 주소 |
| 로그인(인증) | 회원이 누구인지 확인하는 기능 |
| 예시 데이터 | 화면을 먼저 보기 위해 넣어 두는 가짜 데이터. |
| 프리셋 | Preset. 프로킷으로 미리 만들어 둔 서비스. 랜딩페이지 9개, 앱 화면 5개예요. 프리셋 팩으로 같은 서비스를 만들어 보거나 바꿔 만들 수 있어요([프리셋 고르기](../samples/README.md#프리셋으로-만들어-보기)) |
| 프로킷 사이트, 프리셋 사이트 | 프로킷 사이트는 pro-kit-ui 홈페이지([prokit-web.vercel.app](https://prokit-web.vercel.app/))예요. 프리셋을 모아 보고 모든 페이지를 미리 볼 수 있고, 튜토리얼과 문서도 있어요. 프리셋 사이트는 프리셋마다 GitHub Pages에 올린 사이트(`https://prokit-web.vercel.app/pro-kit/<이름>/`)로, 직접 눌러 보며 써 볼 수 있어요 |
| 프리셋 팩 | Preset Pack. 만들 서비스의 화면 구성, 디자인, 예시 데이터, 그림을 묶어 둔 폴더. zip 파일 하나로 받아 풀어요. 프리셋마다 있고, 에이전트가 필요한 팩만 받아 그것만 보고 만들어요. 받는 법은 [프리셋 팩 안내](../samples/README.md#프리셋으로-만들어-보기)에 있어요(에이전트는 `node scripts/pack.mjs <이름>`으로 받아요) |
| 라운드, dev-cycle | 라운드는 기능 하나를 만들거나 요청한 것을 고치고 확인까지 마치는 작업 묶음이에요. 스펙, 구현, 테스트, 리뷰를 거쳐 내가 직접 확인해야 닫혀요. 라운드를 이렇게 돌리는 pro-kit-ui의 절차를 dev-cycle이라고 해요 |
| 케이스 | 라운드에서 하는 작업의 종류. A 경미한 변경, B 화면, C 버그, D 서버와 API, E DB, F 두 곳 이상에 걸친 새 기능, H 스킬과 하네스예요. 종류마다 대조표에 붙는 행이 달라요. 바꾼 파일의 위치로 정해요(버그 수정 C는 경로와 상관없이 에이전트가 선언해요). 애매하면 더 무거운 쪽으로 해요 |
| 코디네이터, 수행자 | 코디네이터는 지금 대화하는 메인 에이전트로, 일을 나눠 맡기고 결과를 모아 확인해요. 수행자는 코디네이터가 정한 파일만 고치는 구현 에이전트예요. 자기가 한 일을 자기가 승인하지 않도록 역할을 나눠요 |
| 전문 리뷰, 최종 리뷰 | 전문 리뷰는 화면 점검이나 DB 점검처럼 한 분야를 깊이 보는 리뷰예요. 최종 리뷰는 읽기 전용 리뷰어(`prokit-reviewer`)가 라운드의 전체 변경을 마지막으로 보는 리뷰이고, 매 라운드 새로 받아요 |
| 공급자 | 위임에서 일을 실제로 맡는 스킬이나 도구. 이름만 보고 고르지 않고 실제 내용과 출처를 확인한 뒤 써요([위임과 자원 관리](https://github.com/roadkwon-ai/pro-kit-ui/blob/main/handbook/concepts/delegation-and-resources.md)) |
| 증거 | 대조표의 칸마다 적는 "실제로 했다는 기록". 실행한 명령과 결과, 만든 파일 경로 같은 것이에요. `ok`나 `완료`만 적은 것은 증거가 아니에요 |
| blocked, 미실행, 부분 완료 | 할 수 없었던 행에는 이유를 붙여 `blocked: 사유`(막힘)나 `미실행: 사유`로 적어요. 이런 행이 남은 채 닫는 것이 부분 완료예요. 에이전트가 먼저 보고하고, 내가 그대로 닫자고 할 때만 `close --partial`로 닫아요. 내가 직접 확인하는 행은 이 방법으로 넘길 수 없어요 |
| ADR | Architecture Decision Record. 왜 이렇게 정했는지 남기는 짧은 결정 기록이에요. 프로젝트의 `docs/adr/`에 쌓여서 나중에 이유를 다시 찾을 수 있어요 |
| guard(자원 보호) | 빌드나 설치가 디스크와 메모리를 너무 쓰지 않게 감시하고, 같은 일이 겹쳐 돌지 않게 막는 장치. 프로젝트 밖의 파일이나 쓰고 있는 환경은 크기만 보고 지우지 않아요([위임과 자원 관리](https://github.com/roadkwon-ai/pro-kit-ui/blob/main/handbook/concepts/delegation-and-resources.md#관리-범위-안-자원만-다루기)) |
| 대조표 | 라운드마다 `tasks/todo.md`에 만드는 체크 표. 단계(행)마다 실제로 한 일의 증거(명령, 결과)를 적어요. 다 채웠는지는 `pnpm dev-cycle audit` 명령이 검사하고, 빈 칸이 있으면 라운드를 닫지 못해요. 마지막 행은 내가 직접 확인하는 `[confirm]` 행이에요 |
| 스펙 | 만들기 전에 기능의 범위와 동작을 적은 문서. 에이전트가 보여 주면 읽고 확인해요 |

## 디자인

| 용어 | 뜻 |
|---|---|
| `PRODUCT.md` | 서비스가 무엇이고 누구를 위한 것인지 적은 기획 문서 |
| `GLOSSARY.md` | 서비스에서 쓰는 말을 정리한 용어집. 에이전트가 같은 대상을 늘 같은 말로 부르게 해 줘요 |
| 사이트맵 | 서비스의 모든 페이지와 페이지 사이의 이동을 정리한 목록 |
| 화면 설계(브리프) | 화면 하나를 만들기 전에 쓰는 짧은 설계 메모 |
| 스타일 카탈로그 | 잘 만든 서비스의 디자인 규칙을 모아 둔 곳. 에이전트가 여기서 어울리는 스타일을 추천해요 |
| `DESIGN.md`, 디자인 토큰 | `DESIGN.md`는 고른 스타일의 색, 글꼴, 간격 규칙을 적은 파일이에요. 그 안의 색, 글꼴, 간격 값 하나하나를 디자인 토큰이라고 해요 |
| comp(시안), plate | comp는 구현하기 전에 AI로 그려 보는 화면 그림이에요. 셋 중 하나를 골라요. plate는 화면에 넣는 사진이나 일러스트예요 |
| 배치도 | 화면마다 무엇이 어디에 놓이는지 그린 그림. 프리셋 팩에 들어 있고, 영어로는 wireframe이라고 해요 |
| 구성도 | 시안 대신 고르기 페이지가 직접 그리는 간단한 화면 구성 그림. 시안을 그리지 않거나 그릴 수 없을 때 써요. 에이전트는 배치도나 wireframe이라고 부르기도 해요 |
| critique, audit, polish | 만든 화면을 평가하고(critique), 접근성·성능 같은 품질을 점수로 점검하고(audit), 지적을 모아 다듬는(polish) 단계. audit은 라운드의 대조표를 검사하는 명령(`pnpm dev-cycle audit`)을 뜻하기도 해요 |
| 디자인 리뷰 점수 | 화면이 쓰기 편한지 AI 디자인 평가 도구가 매긴 점수예요. 사용성 전문가 야코브 닐슨이 정리한 10가지 기준(지금 무슨 일이 일어나는지 알려 주는지, 익숙한 말을 쓰는지, 잘못 눌러도 되돌릴 수 있는지 등)마다 0\~4점을 매겨 40점 만점이에요. 28점 이상이면 좋음, 36점 이상이면 아주 좋음이에요. 첫 화면 하나만 볼 때처럼 해당하지 않는 기준을 빼면 만점이 32점이나 28점이 돼요 |
| 접근성 | 키보드만 쓰거나 화면 읽기 프로그램을 쓰는 사람도 서비스를 쓸 수 있는 정도. 글자 대비, 키보드 이동, 버튼 이름 같은 것을 봐요 |
| P0\~P3 | 디자인 리뷰가 찾은 문제의 급. P0은 할 일을 아예 못 하게 막는 문제, P1은 크게 헷갈리거나 불편한 문제예요. P2는 불편하지만 돌아갈 길이 있는 문제, P3은 다듬으면 좋은 것이에요 |

## 올리기

| 용어 | 뜻 |
|---|---|
| 배포 | 만든 서비스를 인터넷에 올려 누구나 들어올 수 있게 하는 일([배포하기](deploy.md)) |
| Vercel | 웹 서비스를 인터넷에 올려 주는 곳 |
| GitHub Pages | GitHub 저장소의 파일을 무료로 인터넷에 올려 주는 기능 |
| GitHub | git 기록을 인터넷에 올려 두는 곳 |
| 정적 사이트 | 서버 없이 미리 만든 파일만으로 보여 주는 사이트. GitHub Pages에 올린 프리셋 사이트가 이 방식이에요 |

## 계정과 비용

| 용어 | 뜻 |
|---|---|
| 사용량 한도 | 요금제마다 일정 시간에 쓸 수 있는 양. 넘으면 잠시 멈춰요 |
| 비밀값 | 비밀번호, 토큰, API 키, DB 주소처럼 남에게 보이면 안 되는 값. 대화창에 붙여 넣지 않고 `.env` 파일에 두며, 커밋하기 전에 에이전트가 `pnpm dev-cycle secrets`로 섞여 들어갔는지 검사해요 |
| API 키 | 프로그램이 내 계정으로 서비스를 쓰게 해 주는 비밀 열쇠. 비밀번호처럼 다뤄요 |
| 토큰 | 에이전트가 내 GitHub이나 Vercel 계정으로 배포하게 해 주는 비밀 열쇠. 비밀번호처럼 다뤄요. [배포하기](deploy.md#2-계정과-토큰-만들기) |
| 토큰(AI 사용량) | AI가 글을 읽고 쓰는 양을 세는 단위. 한글 한 글자가 대략 토큰 하나예요. 튜토리얼의 "약 440만 토큰"이 이 뜻이에요 |
| `OPENAI_API_KEY` | OpenAI API 키를 적는 항목 이름. 이 키를 넣는 것이 Claude Code로 이미지를 그리는 두 방법 중 하나예요. [이미지 그리기](costs-and-keys.md#이미지-그리기) |
| gpt-image | Claude Code가 Codex CLI를 거쳐 ChatGPT 요금제로 이미지를 그리게 해 주는 스킬. pro-kit-ui가 프로젝트에 설치해요 |
| `.env`, `.env.example` | `.env`는 키 같은 비밀값을 적는 파일이에요. 튜토리얼에서는 작업 폴더 `~/projects`에 하나 만들어 OpenAI 키와 배포 토큰을 적어요. 프로젝트 안의 `.env`는 git이 무시해서 GitHub에 올라가지 않아요. `.env.example`은 무엇을 적을지 보여 주는 예시 파일이에요 |
